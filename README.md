# Стенд изгиба кабеля (ESP32-S3)

Прошивка контроллера стенда, циклически изгибающего кабель поворотом ротора.
Аппаратно повторяет нагрузочный стенд ESP32-S3, но **без тензодатчика**: вместо
поиска и удержания нагрузки выполняется программа изгибных циклов по углу.

## Что делает

- Захватывает логическую домашнюю позицию при загрузке и приводит ротор в центр
  (bend 90°, положение покоя «вверх»).
- По команде запускает программу циклов: вход `90° → 0°`, затем N раз
  `0° → 180° → 0°` с выдержкой в крайних точках, затем возврат `→ 90°`.
- Один цикл - полный размах `0° → 180° → 0°`. Вход и выход в счёт циклов не идут.
- Из любой точки вне прогона выполняет автоматический homing в центр 90°.
- Отдаёт живую телеметрию и принимает команды по REST и WebSocket; параметры
  цикла настраиваются из веб-панели и сохраняются в NVS.

## Геометрия (bend-кадр)

- `0°` - крайнее левое, `90°` - центр/покой (верх), `180°` - крайнее правое.
- Привязка к энкодеру: логический ноль (позиция при homing на
  `HOME_ABSOLUTE_ANGLE_DEG`) соответствует **bend 180°**, поэтому
  `bend_angle = 180 + rel_deg`. Весь ход лежит по одну сторону от анкера, что
  исключает наезд на механическую стенку исходного нагрузочного стенда.
- Амплитуда - половина размаха от центра: `лево = 90 − A`, `право = 90 + A`.
  Полная амплитуда `A = 90` даёт ход `0…180°`; для безопасного теста её можно
  уменьшить из панели.

## Состояния

`BOOT → HOMING → IDLE → RUNNING → RETURN_HOME → IDLE`, плюс `ERROR`.
Программа циклов исполняется внутри `RUNNING` как автомат под-фаз
(`ENTER_LEFT / DWELL_LEFT / TO_RIGHT / DWELL_RIGHT / TO_LEFT / TO_CENTER`).

## Управление

- **Кнопка:** `IDLE` - старт прогона; `RUNNING` - остановка (возврат в центр);
  `ERROR` - повторный homing.
- **Команды API** (`start` / `stop` / `home`): те же переходы. `home` из
  `RUNNING` эквивалентна `stop`.

## Параметры цикла (runtime, NVS)

Задаются через `POST /v1/config`, сохраняются единым blob в NVS:

| Параметр | Ключ | По умолчанию |
|---|---|---|
| Число циклов | `cycles` | 10 |
| Выдержка в крайних точках, мс | `dwell_ms` | 1000 |
| Скорость (интервал шага, мкс) | `speed_us` | 4000 |
| Амплитуда, ° | `amplitude_deg` | 90 |

## Модули

- `esp32s3_bend_stand.ino` - запуск, автомат состояний, программа циклов.
- `Config.h` - пины, геометрия, параметры по умолчанию, сеть.
- `EncoderTracker.*` - AS5600, многооборотный учёт, логический ноль.
- `StepperMotor.*` - импульсы шага и направление.
- `ButtonInput.*` - антидребезг кнопки.
- `ConfigStore.*` - хранение параметров цикла в NVS.
- `NetworkManager.*` - WiFi, mDNS, REST, WebSocket.
- `Telemetry.*` - сборка JSON телеметрии и событий.
- `SystemState.h`, `NetCommand.h` - состояния и разбор команд.

## Требуемые библиотеки

- `AS5600` (Rob Tillaart)
- `AsyncTCP`, `ESPAsyncWebServer` (ESP32Async)

`Wire` входит в ядро Arduino. Тензодатчик и библиотека HX711 в этом проекте не
используются.

## Сборка (PlatformIO)

```bash
pio run                 # сборка под esp32-s3
pio run -t upload       # прошивка
pio device monitor      # монитор порта, 115200
```

## Калибровка и допущения

- `HOME_ABSOLUTE_ANGLE_DEG` - абсолютный угол AS5600, принимаемый за логический
  ноль (= bend 180°). На отладочном стенде взят тот же анкер `106.08°`, что и у
  нагрузочного стенда.
- Направление `+` шага увеличивает угол энкодера. Если механизм идёт не в ту
  сторону, инвертировать знак шага в примитиве движения.
- Пороги окна прихода, детектор застревания и интервалы homing - консервативные
  стартовые значения, донастраиваются на оборудовании.

## Сеть

Учётные данные WiFi заданы в `Config.h` (сеть `tmvos`). Имя хоста -
`1.bend.esp32-s3`, домен `1.bend.esp32-s3.local` при работающем mDNS.
Предпочтительный путь к стабильному адресу - резервирование IP по MAC (печатается
при загрузке). Опциональный статический IP отключён по умолчанию.
